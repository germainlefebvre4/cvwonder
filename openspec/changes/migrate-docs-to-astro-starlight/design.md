# Design

## Context

See `proposal.md` for motivation. Current state that shapes the approach:

- `docs/github-pages/` is a Docusaurus 3.7 site: 41 `.md`/`.mdx` pages, `sidebar_position` frontmatter (40 pages), autogenerated sidebar, no custom slugs (the `slug:` strings found in the docs are inside YAML code blocks), 47 admonitions (`note`, `tip`, `info`, `warning`, `important`), one Mermaid diagram, 22 relative `.md` file links, no versioning, one locale.
- Docusaurus-specific features in use are few: three `!!raw-loader!` imports (`helper.out`, `cv.yml`), `<FontAwesomeIcon>` (about 19 uses in two files), `<CodeBlock>` from `@theme/CodeBlock`, and a React homepage with three components.
- The site is built **only on a release tag** (`github-pages.yml`). No pull request builds it, so a broken link today is discovered at release time.
- `static/cv.yml` (documentation example) and the root `cv.yml` are two separate files that have already diverged.
- `static/helper.out` is generated by the `cli-helper` pre-commit hook from `go run ./cmd/cvwonder`.
- `README.md` deep-links to `https://cvwonder.fr/docs/...` and embeds `docs/github-pages/static/img/logo.svg`.
- The logo is a single black `<path>` (`fill="#000000"`), invisible on a dark background. `themeConfig.image: 'img/social-card.png'` points to a file that does not exist.
- Toolchain: pnpm 10, Node 22 (`.node-version`, CI). Deployment is GitHub Pages via `actions/deploy-pages` to `https://cvwonder.fr`.

## Goals / Non-Goals

**Goals:**
- A static Astro/Starlight site that satisfies the `documentation-site`, `documentation-getting-started` and `documentation-guides` specs.
- No JavaScript framework in the site: a content site with a CSS-only hero demo.
- One source of truth for generated or shared content (CLI help, example CV).
- Failures (broken links, missing redirect targets, accessibility regressions of the accent) caught on pull requests, not at release.
- Ship in phases so the site can go live with partial French.

**Non-Goals:**
- Docs versioning per release. The site documents the latest release only.
- Locales beyond `en` and `fr`.
- Changing CLI behavior or Go code.
- A blog, changelog page or community showcase.
- Rewriting the theme gallery data source (themes remain documented by hand).

## Decisions

### D1. Starlight over bare Astro
Starlight provides sidebar autogeneration, i18n routing with fallback, Pagefind search, dark mode, tabs, steps, cards and an admonition syntax compatible with the existing `:::` blocks. Bare Astro would mean building all of that for a one-maintainer project.
*Alternatives*: bare Astro (more code to maintain, only justified by a non-docs identity); staying on Docusaurus (does not remove React or the Infima look, no gain).

### D2. Migrate in place, keep `docs/github-pages/`
Keeping the directory avoids touching `Makefile` paths, `.gitignore`, the pre-commit hook and the workflow's `working-directory`. The directory name is a misnomer but harmless. Only the output directory changes (`build/` to `dist/`).
*Alternative*: rename to `docs/site/` (cleaner name, but churn in every referencing file for no user-visible gain).

### D3. Static assets move to Astro conventions
- Public files (favicon, share image, logos) go in `public/`, replacing `static/`. `README.md`'s logo reference is updated; the README uses a `<picture>` with light and dark logo variants so it also works in GitHub dark mode.
- Files that pages **import** (`helper.out`, the example CV) move to `src/generated/` and `src/examples/` and are loaded with Vite's `?raw` import, then displayed with Starlight's code component. They are no longer published as stray public files (today `/helper.out` and `/cv.yml` are publicly served as a side effect).
- The `cli-helper` pre-commit hook's output path is updated to `docs/github-pages/src/generated/helper.out`.

### D4. One example CV, validated in CI
`static/cv.yml` and the root `cv.yml` have diverged. The documentation example becomes the single copy under `docs/github-pages/src/examples/cv.yml`, and a CI step runs `cvwonder validate --input <that file>` so the displayed example cannot rot. Reconciling the two files (which one is current) is done by running `cvwonder validate` against both and keeping the valid, more complete one.
*Alternative*: import the root `cv.yml` directly from outside the project root (requires Vite `fs.allow` and couples the site to a repo-root file that is also used for local testing).

### D5. i18n: English at the root, French under `/fr/`
Starlight `locales` with `root` = English and `fr`. Content lives in `src/content/docs/` (English) and `src/content/docs/fr/` (French). Starlight's fallback serves English content with a notice for untranslated French pages, which implements the launch-scope decision (core path translated, the rest in fallback). Absolute site links are written per locale (`/start/install/` and `/fr/start/install/`).
*Alternative*: French as the default locale (rejected: English is the broader audience and the existing content).

### D6. URL scheme and redirects
- `site: 'https://cvwonder.fr'`, `trailingSlash: 'always'`, directory output format.
- Content folders replace the old structure (Start, Guides, Themes, Reference, Contribute). Old-to-new mapping lives in one file, `redirects.ts`, fed to Astro's `redirects` option, which emits `meta-refresh` HTML pages (GitHub Pages cannot send 301).
- The old URL list is derived from the current `docs/` tree before it is moved, committed as a fixture, and a CI check asserts that each old URL has a redirect and that each redirect target exists in `dist/`. `/docs/` itself redirects to `/start/`.
- `<link rel="canonical">` on redirect pages comes from the emitted redirect HTML, which helps search engines consolidate. The generated `sitemap.xml` replaces Docusaurus's and is submitted to search consoles after launch.
*Alternative*: keep `/docs/` by nesting content in `src/content/docs/docs/` (would yield `/fr/docs/...`, and keeps a meaningless segment); rejected with the user.

### D7. Information architecture
```
Start        install, first-cv                      (documentation-getting-started)
Guides       bulk-mode, theme-customization,
             validate-your-cv, export-pdf-and-html   (merges export/ and validation/ prose)
Themes       gallery, use, install-remote,
             write, publish, troubleshooting
Reference    cli (commands, options, help output),
             yaml-schema, theme-functions, common-errors
Contribute   architecture, development, workflow, release, code of conduct
Footer       license
```
Page ordering uses Starlight's `sidebar.order` frontmatter (converted from `sidebar_position`); sections use `autogenerate` so new pages need no sidebar edit.

### D8. Replacing Docusaurus-specific constructs

| Docusaurus | Replacement |
|---|---|
| `!!raw-loader!` + `<CodeBlock>` | `?raw` import + Starlight/Expressive Code `<Code>` with `title` |
| `<FontAwesomeIcon>` in `<summary>` (13x) | plain `<details><summary>`, icon dropped |
| `<FontAwesomeIcon>` colored dots in license table | CSS-colored markers or plain list; no icon library |
| `:::important` (2x) | `:::caution` if it warns of a consequence, `:::note` otherwise, decided per page |
| `:::info`, `:::warning` | `:::note`, `:::caution` (Starlight names) |
| Relative `.md` links (22) | site-absolute links, locale-prefixed for French pages |
| React homepage + 3 components | `splash` template with `.astro` components and CSS only |
| Mermaid theme plugin | `astro-mermaid` integration for the single diagram (alternative: commit a rendered SVG) |
| `onBrokenLinks: 'throw'` | `starlight-links-validator` in the build |
| Docusaurus footer/navbar items | Starlight `sidebar`, `social`, `components` overrides for header links |

### D9. Visual identity
- Tokens: accent `#c2410c` (light) / `#fb923c` (dark), cool neutral surfaces, Starlight's accent variables overridden in one CSS file. Semantic colors for caution/danger stay separate from the accent.
- Contrast is enforced by a small Node script run in CI that computes WCAG ratios from the CSS tokens and fails below 4.5:1.
- Typography: self-hosted variable fonts via `@fontsource` (no third-party font requests), a single sans (Inter) for body and headings.
- Logo: two files, `logo-light.svg` and `logo-dark.svg`, passed to Starlight's `logo.light`/`logo.dark`, derived from the existing single-path vector.
- Hero: an Astro component rendering the `init`, `serve`, `generate` demo as styled terminal lines with a CSS animation (`steps()` typing), disabled under `prefers-reduced-motion`; text passed as props so the French homepage reuses it.
- Theme previews: tall screenshots (800x1643, 800x2831) are shown in fixed-aspect cards using `object-fit: cover` and `object-position: top`.
- Share card: one 1200x630 PNG in `public/`, referenced through Starlight's `head` config with an absolute URL.

### D10. Version in the header
`CVWONDER_VERSION` is read in `astro.config.mjs` (default `dev`) and exposed to a small header component (Starlight `SocialIcons` override) rendering the version link next to the GitHub link.

### D11. CI
- `github-pages.yml`: upload `docs/github-pages/dist/`, keep the tag trigger and the `CVWONDER_VERSION` injection.
- New `docs.yml` workflow on pull requests touching `docs/github-pages/**`, `cmd/**` (for the help output) or the example CV: install, build (link validation runs here), redirect check, contrast check, and `cvwonder validate` on the example CV.
- `Makefile` targets `doc-install`, `doc-build`, `doc-serve` keep their names.

## Risks / Trade-offs

- **SEO continuity through `meta-refresh` redirects** (no 301 on GitHub Pages) -> redirect map covers every old URL, canonical links on redirect pages, new sitemap submitted, README deep links updated to new URLs.
- **French search may not index fallback pages as French.** The spec says French search includes pages shown in fallback; Pagefind's per-language indexes may instead file them under English -> verify in the skeleton phase; if so, amend the spec to say fallback pages are searchable from the English site only.
- **Version compatibility of Astro, Starlight and the plugins** (`astro-mermaid`, links validator) moves faster than Docusaurus -> pin exact versions in `package.json` and the lockfile, confirm the Node requirement against Node 22 before starting, let Dependabot propose updates.
- **French quality**: translations are drafted by Claude and reviewed by the maintainer -> French launch scope is limited to the core path so review stays tractable; translated pages carry no "machine-translated" label, so the review step must not be skipped.
- **Content rewrite scope** (about 15,000 words) -> phased by section, English first, the site is releasable after each phase because navigation and redirects land in the skeleton phase.
- **Losing Docusaurus conveniences** (`write-heading-ids`, built-in 404 handling): Starlight generates heading anchors itself and ships a 404 page; deleting or renaming headings can still break anchors, which the links validator catches.
- **Docker example inconsistency** (`docker.md` mounts `/cv` but explains `/app`) -> fixed during the rewrite and covered by a spec scenario.

## Migration Plan

1. **Skeleton**: scaffold Starlight in place, port config (site URL, locales, edit link, header links), move existing content as-is into the new structure with converted frontmatter and links, add the redirect map, links validator, PR workflow, update `Makefile`, `.gitignore`, pre-commit and `github-pages.yml`, delete Docusaurus. Spike the French-search behavior here.
2. **Identity**: tokens, fonts, logo variants, homepage with hero, theme preview cards, share card.
3. **English content**: rewrite section by section in the order Start, Guides, Themes, Reference, Contribute.
4. **French content**: translate the launch scope, then review.
5. **Verification**: full build, redirect and contrast checks, manual pass on light/dark and mobile, Lighthouse, README link update.

Deployment is atomic: GitHub Pages serves the previous build until the new tag build is deployed. **Rollback** is re-running the previous tag's `github-pages` workflow (the Docusaurus build remains reproducible from its tag). The change merges to `main`, and the site goes live at the next release tag.

## Open Questions

- Exact font pair for body and display headings (decided against the mockups in the identity phase; does not change specs or tasks).
- Whether the `:::important` admonitions map to `note` or `caution` (decided page by page while converting).
- Whether to keep a lightweight `/themes/gallery/` page generated from `theme.yaml` metadata or keep it hand-written for now (hand-written in this change).
