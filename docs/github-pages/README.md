# CV Wonder documentation

The documentation of [cvwonder.fr](https://cvwonder.fr) is built with [Astro](https://astro.build/) and [Starlight](https://starlight.astro.build/).

## Layout

- `src/content/docs/`: English pages (served at the root); `fr/` holds the French translations.
- `src/examples/cv.yml`: the example CV shown in the docs; validated in CI with `cvwonder validate`.
- `src/generated/helper.out`: the CLI help output, regenerated by the `cli-helper` pre-commit hook.
- `redirects.ts`: legacy `/docs/...` URLs mapped to their new location.
- `scripts/`: build checks (`check-redirects.mjs`, `check-contrast.mjs`, `check-landing.mjs`).
- `src/components/` and `src/scripts/`: the animated landing page (see below).
- `src/i18n/landing.ts`: English and French labels of the landing page.

## Commands

Run from this directory, with Node 24 and npm:

| Command | Action |
| --- | --- |
| `npm ci` | Install dependencies |
| `npm run dev` | Start the local dev server at `http://localhost:4321/` |
| `npm run build` | Build the site into `dist/` (fails on broken internal links) |
| `npm run preview` | Serve the built site locally |
| `npm run check:redirects` | Check every legacy URL redirects to an existing page (needs a prior build) |
| `npm run check:contrast` | Check the WCAG contrast of the accent color and gradient-text tokens |
| `npm run check:landing` | Check the landing page: rail and skip targets exist, the animation script is only on the landing pages and stays under 60 KB gzip (needs a prior build) |

The header shows the release version read from `CVWONDER_VERSION` (`dev` when unset).

## Landing page

The landing pages (`src/content/docs/index.mdx`, `fr/index.mdx`) are built from these parts:

- `Hero.astro` replaces Starlight's hero (only the two landing pages; the 404 keeps the default). It renders the title split into words, the tagline and actions from the frontmatter, a "See how it works" link, the terminal, the floating CV, the aurora background, the section rail and the "Skip the demo" pill.
- `Scene.astro` is the "YAML to CV" scene. The MDX passes its YAML example and the three theme previews.
- `Cta.astro` is the closing call to action; the "Why CV Wonder" and "Where to start" sections are Starlight cards wrapped in `<section id="why">` and `<section id="start">`.
- Section ids are `intro`, `scene`, `why`, `start`, `get-started`, identical in both languages. The rail, skip and hero links are plain `#id` anchors, so they stay on the current language.

`src/scripts/landing.ts` is the only client entry. It runs the navigation right away and loads `animate.ts` (GSAP and ScrollTrigger) after first paint. Pages other than the landing receive none of it.

**Scene moments** (`MOMENTS` in `src/scripts/animate.ts`, on a 0 to 100 timeline pinned for about 4.4 screens at 900 px and wider): act 1 *write* (0 to 25), act 2 *generate* (26 to 60: lines fly away, CV enters, veil render with scan line, HTML and PDF badges, CV scroll), act 3 *theme* (61 to 100: two wipes, at 72 and 90). The act tabs, theme chips, the `theme:` YAML line and the progress bar all derive from these moments. The scene is a direct function of scroll: it never captures the wheel or snaps.

**Without animation**: the default markup is the complete page. With reduced motion, without JavaScript, or if the library fails to load, nothing is hidden: the hero text, terminal, YAML, every section and the call to action are shown. Below 900 px (and with reduced motion) the theme chips become a tab set showing one preview at a time; without JavaScript the three previews are stacked as captioned figures.

**Colors**: the aurora uses `--cvw-aurora-1` to `-3` and the title gradient `--cvw-grad-1` to `-3` in `src/styles/theme.css`, each with a dark and a light value. Aurora hues are decorative only; every gradient stop must reach 4.5:1 against the background, which `npm run check:contrast` enforces.

## Deployment

The `github-pages` workflow builds and publishes `dist/` to GitHub Pages on each release tag.
